# practic-5
Відповіді на контрольні запитання для захисту роботи
1. У чому полягає фундаментальна відмінність життєвого циклу сторінки в класичному MPA порівняно зі SPA під час переходу за внутрішніми навігаційними посиланнями?
MPA (Multi-Page Application): Кожен перехід за посиланням ініціює новий повноцінний HTTP-запит до сервера. Поточний документ повністю знищується, контекст виконання скриптів анулюється, стилі та DOM-дерево завантажуються й парсяться наново з нуля.

SPA (Single-Page Application): Сервер завантажує єдиний HTML-каркас один раз. Подальші переходи виконуються клієнтським JavaScript: старий контент приховується або видаляється з DOM, а новий рендериться динамічно. Життєвий цикл сторінки не переривається, а єдиний глобальний контекст виконання зберігається.

2. Які зміни фіксуються у вкладці Network браузера під час клієнтської маршрутизації в реалізованому SPA порівняно з переходом між окремими HTML-файлами?
Під час клієнтської маршрутизації в SPA у вкладці Network не з'являються нові запити типу document чи fetch/XHR для завантаження розмітки розділів (адже весь інтерфейс та логіка вже завантажені первинно). Фіксується лише зміна URL-хешу (#section), яка відбувається локально.

У класичному MPA кожне натискання на посилання створює новий мережевий запит за іншим .html файлом, що супроводжується передачею повного пакету розмітки від сервера.

3. Чому глобальний стан виконання JavaScript (активне відтворення медіафайлу або поточні значення змінних) руйнується при навігації в MPA-моделі?
При переході між сторінками в MPA браузер повністю очищає оперативну пам'ять від попереднього контексту виконання (JavaScript Context Execution). Усі змінні, об'єкти, стани таймерів (setInterval) та потоки медіа (<audio>) знищуються під час вивантаження старої сторінки, а нова сторінка ініціює виконання скриптів із «чистого аркуша».

4. Які переваги та обмеження має чистий клієнтський SPA у порівнянні зі стратегіями серверного рендерингу (SSR) та статичної генерації (SSG) щодо швидкості первинного завантаження та індексації пошуковими системами (SEO)?
Переваги SPA: Миттєва навігація після первинного завантаження, плавні переходи, зручність підтримки безперервного глобального стану (аудіо, сесії, кеш).

Обмеження SPA:

Первинне завантаження (First Load): Повільніше, оскільки браузер мусить завантажити великий бандл JS перед початком рендерингу.

SEO: Пошукові роботи можуть бачити порожній <body> під час первинного запиту, якщо бот не виконує повний рендеринг JavaScript (хоча сучасні краулери від Google виконують JS, це складніше, ніж статичний SSR/SSG).

SSR та SSG вирішують ці проблеми, генеруючи готову HTML-розмітку на сервері або під час зльоту білду, проте вимагають складнішої інфраструктури.

5. Поясніть сутність процесу гідратації (Hydration), характерного для додатків із серверним рендерингом (SSR).
Гідратація (Hydration) — це процес, під час якого клієнтський JavaScript «ожвавлює» статичний HTML-документ, згенерований сервером (SSR). Сервер надсилає повністю готову, візуально готову розмітку (що забезпечує миттєвий показ сторінки та ідеальне SEO), проте без обробників подій. Коли браузер завантажує скрипти, він проходить по DOM-дереву, підключає слухачі подій (addEventListener), відновлює стан та робить сторінку інтерактивною.
